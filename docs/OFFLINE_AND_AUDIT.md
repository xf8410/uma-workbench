# 多仓库审计与离线优先

## 仓库身份卡

每个来源先记录用途、语言、默认分支、最近提交、Release、CI、Issue/PR 活跃度、适用版本、Fork/镜像关系、可运行性和资料时效性。
“不可构建”不等于“无研究价值”；旧版本资料保留为历史证据。

## 去重策略

以 Git Blob SHA-256、归档内容哈希和文件指纹识别重复内容。克隆仓库不做完整重复扫描，但必须扫描独有文件、提交、配置、Issue/PR 和版本差异，并记录复用范围。

## 子任务阶段

1. 发现来源和元数据
2. 文件清单与哈希
3. 文本/代码索引
4. 二进制字符串索引
5. DB/Master/metadata Schema
6. 候选端点和风险提取
7. 版本聚类
8. 跨来源关联
9. 冲突和过时性审计
10. 中文语义摘要

每阶段独立持久化，禁止单次请求全仓库全文载入。

## 离线优先

消息、审计请求、上传块、任务事件和记忆加载状态先落本地。网络切换只改变同步状态，不改变任务事实。恢复网络后按幂等键同步，成功块和 checkpoint 不重复执行。

缓存分为：可重建 Cache、主动保存的 Offline data、不可自动删除的原始 Archive。用户可查看大小、最近同步时间、待同步任务和失败原因。
