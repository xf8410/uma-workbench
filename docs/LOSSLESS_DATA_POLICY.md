# 无脱敏、无损研究数据策略

## 用户决定

UMA Workbench 是用户自己的本地研究工具。Token、Cookie、Authorization、请求头、协议正文、设备字段、原始日志和崩溃上下文都可能是定位问题所需证据。

因此产品执行以下硬规则：

1. 不实现自动脱敏；
2. 不实现默认脱敏；
3. 不实现日志脱敏；
4. 不实现报告脱敏；
5. 不实现预览脱敏；
6. 不因字段名像 `token`、`cookie`、`authorization`、`password` 就替换内容；
7. 不静默省略、掩码、截断或摘要化原始证据；
8. 原始导入、索引、显示、诊断和导出保持内容可见且可复核。

## 安全不等于隐藏数据

保留的安全机制是控制副作用和外发目的地，而不是改变研究数据：

- 删除需要明确确认；
- 安装、部署、清空捕获需要明确确认；
- GitHub 上传、PR、合并、Workflow dispatch 等远程写操作需要明确确认；
- 未知插件显示来源和风险；
- 工作区限制读写范围；
- 外部上传前显示仓库、可见性、分支、目标路径、文件数量和总字节数；
- 任何确认都只授权操作，不得改写文件正文。

## 凭据保存与研究数据展示的区别

- 应用自己用于登录 GitHub/模型服务的长期 API Key，仍应保存在 Android Keystore/系统凭据存储中，不写入 Git 仓库或普通配置文件；
- 用户主动导入或 SO 捕获到的 Token/Cookie/Authorization 属于研究数据，应完整显示、索引和导出；
- 两者不能用同一条“敏感字段过滤器”处理。

## 原始与派生层

```text
原始层：字节和文本保持不变
索引层：保留来源、偏移、哈希和完整值
派生层：可生成摘要，但不能替代或删除原始值
报告层：默认允许引用完整证据
外发层：由用户确认目的地，不自动改变内容
```

## 测试门禁

代码库必须有回归测试，确保包含下列字段的消息仍逐字保留：

```text
Authorization
Cookie
token
password
raw protocol bytes/text
```

发现 `[REDACTED]`、掩码替换、敏感字段过滤或静默省略逻辑时，应视为数据完整性回归，除非它只作用于应用自身凭据 UI 且不接触研究数据。
